# LocalType × OpenTypeless：桌面产品差距与实施范围

> 状态：桌面主界面实施前的产品基线  
> 日期：2026-08-24  
> 参考：[OpenTypeless 官方仓库](https://github.com/tover0314-w/opentypeless)、[官方产品页](https://www.opentypeless.com/en)

## 1. 结论

OpenTypeless 最值得借鉴的不是某一种卡片样式，而是它把语音输入从“后台快捷键”组织成了一个完整产品：主工作区、听写历史、个人词典、场景适配、模型与快捷键设置、录音胶囊和首次运行引导都有明确入口。

LocalType 当前的核心识别体验已经成立，而且在中文、本地 GPU、终端安全输入和隐私方面更有辨识度。下一步不应复制 OpenTypeless 的云服务、账户、订阅或多供应商复杂度，而应围绕以下闭环补齐桌面产品：

1. 用户随时看得懂系统是否就绪，以及按什么开始。
2. 每次听写都能查看原文、整理结果、目标应用和处理状态。
3. 识别错误可以直接沉淀为个人词典或纠错规则。
4. 不同应用可以使用不同写作风格，同时终端始终执行更严格的安全策略。
5. 模型、显存、快捷键和隐私状态可以在一个地方管理。

## 2. 产品取舍

| 能力 | OpenTypeless | LocalType 当前 | LocalType 决策 |
|---|---|---|---|
| 全局听写 | 支持多快捷键与录音胶囊 | `F9` 智能、`Shift+F9` 原文 | 保留已验证交互，主界面提供同一操作入口 |
| 语音识别 | 多云端/本地供应商 | Qwen3-ASR-1.7B 本地 GPU | 首版坚持单一高质量本地模型，降低配置负担 |
| AI 整理 | 多 LLM/BYOK/云端 | Qwen3-0.6B 本地保守整理 | 保留本地默认，强化可解释回退与原文对照 |
| 历史 | 搜索、复制、应用上下文、纠错入口 | 仅保存最近一次文本 | P0 建立本地历史，默认不保存音频 |
| 个人词典 | 词语、发音、纠错规则、导入导出 | JSON 映射，需外部编辑器 | P0 图形化增删；P1 支持搜索、导入导出与建议 |
| 场景适配 | 应用分类、用户映射、样式规则 | 仅把当前窗口类名传给校对模型 | P1 引入内置场景和自定义应用映射 |
| 选中文字编辑 | 改写、摘要、翻译、问答 | 不支持 | P2；Wayland 下明确标为实验性能力 |
| Ask Anything | 独立语音问答与答案浮窗 | 不支持 | P2；必须与听写模式明确分开 |
| 翻译 | 独立模式和目标语言 | 不支持 | P2；不挤进首版主工作区 |
| 模型与资源 | 供应商配置为主 | 固定本地模型，可查看 GPU | P0 把模型健康、显存、服务重启做成一等状态 |
| 账户与订阅 | 支持账户、云额度和升级 | 无 | 不进入 Omarchy 版，保持本地无账户体验 |
| 跨平台 | Tauri，Windows/macOS/Linux | Omarchy/Hyprland 插件 | 当前主界面使用 QML；长期仍迁移到 Tauri 2 |

## 3. 桌面主界面信息架构

视觉方案可以不同，但首版桌面应用共享同一套导航和能力边界。

### 3.1 工作区

- 明确展示 `Ready / Recording / Processing / Error`。
- 主操作为开始或停止听写，状态和 `F9` 行为一致。
- 切换智能听写与原文听写。
- 展示当前应用、匹配场景和终端安全策略。
- 展示最近一次整理结果，支持复制与查看原文。

### 3.2 历史

- 按日期展示本地听写记录。
- 每条记录包含：整理结果、ASR 原文、模式、目标应用、时间、输出状态。
- 支持搜索、复制、删除单条和清空全部。
- 可从一条错误记录创建词典映射。
- 默认只保存文字和元数据，不保存 WAV 音频。

### 3.3 词典

- 添加“听到的词 → 应输出的词”映射。
- 搜索、编辑、删除并即时生效。
- 对专有名词、产品名、英文缩写和人名提供示例说明。
- 后续加入导入、导出和重复纠错建议。

### 3.4 场景

- 内置 `Terminal`、`Prompt`、`Chat`、`Document` 四类。
- 场景属性包括：整理强度、标点、段落结构、Markdown、代码/路径保护。
- 应用匹配优先使用 Hyprland `class`，再使用标题规则。
- 终端安全规则不可被普通写作风格关闭。

### 3.5 模型

- 显示 ASR 和校对模型、GPU、显存、服务健康和加载状态。
- 提供重启服务与诊断入口。
- Omarchy 首版不提供未经验证的任意模型切换，避免显存和依赖组合失控。

### 3.6 设置

- 快捷键说明与冲突状态。
- 默认听写模式、是否保留文字历史、历史保留期限。
- 输入方式与终端粘贴策略说明。
- 数据位置、隐私说明、版本、自检和卸载入口。

## 5. 实施顺序

### P0：桌面应用闭环

- 可从应用菜单、状态栏和 `localtypectl open` 打开主界面。
- 工作区、历史、词典、模型、设置五个可用页面。
- 听写历史本地持久化，支持搜索、复制和删除。
- 词典可在界面中增删并即时生效。
- 主界面与 F9 使用同一个录音状态机，不产生第二套服务。
- 安装器创建 `.desktop` 启动项并保持升级幂等。

### P1：应用感知写作

- 加入场景页面和四个内置预设。
- 识别当前 Hyprland 应用并显示命中的场景。
- 校对提示词由场景规则组成，而不是只拼接应用类名。
- 历史记录显示场景、耗时和安全回退原因。

### P2：语音操作

- 选中文字后语音改写、摘要或翻译。
- Ask Anything 独立快捷键和答案浮窗。
- 独立翻译模式与目标语言。
- Linux/Wayland 不可靠的能力明确显示兼容性状态。

## 6. 首版验收标准

1. 桌面主界面是真实窗口，不是放大的状态栏弹窗。
2. 窗口关闭不会停止后台听写服务；后台服务停止也不会导致界面崩溃。
3. F9、主界面录音按钮和状态栏入口共享同一状态，不会重复录音。
4. 历史、词典和设置的核心操作可用，不是静态展示。
5. 终端输入仍保持“整段粘贴、不按回车、不自动执行”的安全约束。
6. 所有音频推理保持本地，默认不保存音频，不增加账户和遥测。
7. 视觉实现通过同尺寸参考图对比与实际窗口交互检查。

## 7. 不照搬的部分

- 不复制 OpenTypeless 的付费升级、账户、云词额度和供应商营销界面。
- 不在首版暴露大量模型参数或未经验证的模型组合。
- 不把全部功能堆进首页；首页只围绕“开始听写并确认结果”。
- 不让场景适配削弱终端安全和原文回退。
- 不为了跨平台抽象而推迟 Omarchy 上已经可验证的产品体验。
